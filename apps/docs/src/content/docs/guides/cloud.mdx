The repository supports account-owned uploads through the CLI and hosted MCP.
The hosted services are currently offline; see [hosted availability](../../reference/planned-features/).
For a working account and upload walkthrough, start the [full local workspace](../../reference/development/#full-local-workspace).

<span id="what-is-available-in-staging"></span>

## Upload and open

Upload one HTML file or an artifact folder with [the CLI](../cli/#cloud-upload)
or [MCP](../mcp/). An artifact needs a root `index.html`, may contain up to 512
files, and must fit within 8 MiB including its manifest. CLI uploads support
the documented HTML, script, text, image, font, and media formats. MCP bundles
accept UTF-8 text assets.

The workspace lists documents owned by the signed-in account. A preview requires
that account's browser session. Its HTML runs in an opaque-origin sandbox and
cannot access the workspace's cookies or browser storage. Relative stylesheets,
scripts, and module imports resolve from the entry file. Binary assets can be
previewed but are not returned as text by MCP.

UploadThing object URLs are public during alpha. Account checks and preview
sandboxing do not make provider storage private. Avoid secrets and sensitive
documents; see [privacy and limits](../../reference/privacy-and-limits/).

## Editing and deletion

Uploads create separate documents. Upload a revised file with a clear title to
preserve the original. Stable document revisions are a proposal, not current
behavior.

Deletion hides a document and queues provider cleanup. Cleanup retries failures;
previously downloaded copies remain outside the service's control.

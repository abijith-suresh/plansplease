Install a [repository-built tarball](../install-cli/)
before running these commands. The command is `plansplease`. Existing scripts
that invoke `planview` must update the command name; there is no compatibility alias.

## Local snapshots

```sh
plansplease publish --open ./report.html
plansplease publish --json ./report.html
plansplease publish --open ./artifact/
```

A file must be `.html` or `.htm`. A folder must have root `index.html` and may
contain up to 512 regular files. The encoded snapshot, including a folder's
manifest, must fit within 10 MiB. Symlink sources are rejected.

Each publication creates an immutable snapshot. The daemon prefers port 4777
and selects another available port when necessary. Use the exact printed URL.
Folder pages resolve their assets beneath that URL; the browser follows a root
redirect to serve `index.html`.

### Retrieve a standalone snapshot

```sh
plansplease get <id-or-exact-local-url> > recovered.html
```

`get` writes exact HTML bytes to standard output. It accepts local references
for the selected profile's current port, not cloud links. Current CLI retrieval
does not follow the folder-root redirect, so use the browser to view a local
artifact folder and its assets.

## Daemon and profiles

```sh
plansplease status --json
plansplease start
plansplease stop
plansplease restart
plansplease clean
plansplease --profile work publish ./report.html
```

`status` inspects without starting the daemon. `clean` removes snapshots older
than 30 days since last access and reconciles incomplete storage operations.
The daemon runs that cleanup at startup and every 24 hours. Profiles isolate
local documents, daemon state, and saved cloud credentials.

## Cloud upload

<Code code={`plansplease login --cloud-url http://127.0.0.1:3000\nplansplease upload --open ./report.html\nplansplease upload --json ./report.html\nplansplease logout`} lang="sh" />

Login opens browser sign-in and authorizes this computer for uploads. The saved
credential is upload-only. It cannot list, read, or delete cloud documents.
Logout revokes it on the server before removing the local credential; it needs
a connection. Browser sign-out and CLI logout are separate operations.

Use `--cloud-url` on `login`, or `PLANVIEW_CLOUD_URL`, to select another app origin.
Existing saved credentials remain tied to the origin used at login.
Cloud uploads accept standalone HTML or an artifact folder up to 8 MiB. The
local workspace example uses the local app; hosted service availability is in
the [features reference](../../reference/planned-features/).

## Automation

Errors go to stderr and failures return exit status 1. Successful commands write
their result to stdout. `--json` emits one JSON value for publication, cloud
upload, status, start, stop, restart, and clean. Avoid parsing human-readable
status messages.

```sh
plansplease help
plansplease help upload
npx skills add https://github.com/abijith-suresh/plansplease/tree/main/apps/cli/skills
```

Use `npx skills add ./apps/cli/skills` from a plansplease checkout. Vercel Skills
CLI installs into the current project by default; add `-g` for optional
user-wide installation across projects, and `-a codex -y` for a non-interactive
Codex installation.

## Inventory and selected deletion

```sh
plansplease list --limit 50 --json
plansplease list --after <nextAfter> --limit 50 --json
plansplease usage --json
plansplease delete <id> --generation <generation-from-list> --json
```

These commands start or reuse the selected profile's daemon, including startup
cleanup. After updating the installed CLI, restart the selected profile daemon
to load its new operations. Inventory reads at most 100 metadata rows per page, ordered by ID.
`nextAfter` is omitted on the final page. Pages reflect current metadata, so a
concurrent publication before the cursor appears on a fresh traversal. Listing
and usage never extend retention. Each row includes `createdAt`, `lastAccessedAt`,
`size`, immutable `generation`, and `expiresAt` as epoch milliseconds. Expiry is
30 days after last access; cleanup removes rows strictly older than that boundary.
A successful document read can move expiry later.

`usage` reports logical committed bytes, split into document bytes and a fixed
4 KiB metadata charge per snapshot, plus the 1 GiB quota and retention period.
It does not measure physical disk use, SQLite allocation, staging, or orphan files.

Deletion requires the ID and generation from inventory. It never deletes cloud
copies. An active read retains both the metadata and file; retry after the read
finishes. A stale selection returns `stale`; list again before selecting a new
generation. Deletion can also return `deleted`, `not_found`, `retained`, or
`partial`. Only `deleted` and `not_found` exit with status 0. Removal flags describe
confirmed changes; `fileState` can be `unknown` after a storage failure.

A failure after metadata removal can leave an invisible orphan file. The result
reports `partial` and `recovery: "clean"`; run `plansplease clean` to resume the
existing bounded reconciliation. Fresh orphan files stay until the recovery grace
period passes. Reconciliation also runs after daemon restart. A metadata commit
whose acknowledgement fails is partial unless a read proves the selected
generation is still retained; then retry the selection. `recovery: "inspect"`
means the metadata state could not be established; list again before choosing
any retry. No automatic retry or cloud deletion occurs. If a response is lost, list again and use cleanup
for residual storage; never substitute a different generation in a blind retry.

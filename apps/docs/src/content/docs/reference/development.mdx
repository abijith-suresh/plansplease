Use Node.js 24.19.0 and npm 11.16.0, matching `.node-version` and the package metadata.

```sh
npm ci
npm run verify
npm run changeset:status
npm run pack:check
```

Verification runs formatting, lint, workspace typechecks, tests, and builds.
Tests use local fixtures and do not need production accounts. The public CLI
requires a patch Changeset for user-facing changes before 1.0.0. Publishing is
disabled until maintainers explicitly enable it.

## Full local workspace

After `npm ci`, run `npm run local` from the repository root. Open
`http://127.0.0.1:3000` and create a local test account. The command starts the real
browser app, anonymous local Convex backend, filesystem storage, marketing site
on port 4300, and docs on port 4301. Accounts, sessions, metadata, and document
bytes persist in the ignored `.planview-local/` directory across restarts.

The app has an **Upload document** control with file selection and drag and drop.
CLI login uses the same account:

```sh
node apps/cli/dist/index.js --profile local-dev login --cloud-url http://127.0.0.1:3000
node apps/cli/dist/index.js --profile local-dev upload ./example.html
node apps/cli/dist/index.js --profile local-dev logout
```

HTTP MCP clients connect to `http://127.0.0.1:3000/mcp` and complete real OAuth
with the local account. Native clients can register loopback callbacks and use
PKCE. No GitHub, Convex account, UploadThing token, or paid hosting is required.
The first run downloads the local backend binary. The runner isolates its env
and deployment selection from existing `.env.local` files and cloud credentials.

Ctrl-C stops the services and keeps data. To delete this checkout's local dataset,
stop the runner and explicitly run:

```sh
npm run local:reset -- --yes
```

See the repository's [full local development guide](https://github.com/abijith-suresh/planview/blob/main/LOCAL_DEVELOPMENT.md)
for reset boundaries, source watching, browser preview safeguards, and acceptance
checks. These development services are intended for loopback use on this computer.

## Work on the docs

```sh
npm run dev --workspace @planview/docs
npm run typecheck --workspace @planview/docs
npm test --workspace @planview/docs
npm run build --workspace @planview/docs
npm start --workspace @planview/docs
```

Public URL configuration is read at build time. `PUBLIC_DOCS_URL` selects the
canonical docs origin and optional path prefix. `PUBLIC_APP_URL` and
`PUBLIC_SITE_URL` select workspace and marketing links. Copy `apps/docs/.env.example`
to `.env.local` when you need local overrides. Rebuild after changing a URL.
The production server reads `PORT` and exposes `/health`; it serves only built files.

## Work on the app with a hosted backend

Select a **development** Convex deployment you control and generate its bindings:

```sh
cd apps/app
npx convex deployment select <team>:<project>:dev/<name>
npx convex dev --once
```

Then return to the repository root:

```sh
npm run dev --workspace @planview/app
```

Use `apps/app/.env.example` and the app README for configuration. App and Convex
need compatible origins and matching server-side proof secrets. GitHub credentials
belong in the backend configuration; UploadThing credentials remain server-only.
Do not give them a `PUBLIC_` or `VITE_` prefix.

For a hosted MCP client, point it at your chosen app's `/mcp` route. The staging
endpoint is:

<Code code={`${appUrl}mcp`} lang="text" />

## Deployment boundaries

Marketing, docs, and app are separate services built from the repository lockfile.
A docs deployment needs public URL settings and a Node static server, not Convex
or UploadThing credentials. The cloud app needs a matching Convex deployment.

The merged quota implementation requires a coordinated upload maintenance window,
backend initialization, and compatible app release. Read `apps/app/README.md`
before deploying it beneath an older uploader. These development notes are not a
supported self-hosting installation recipe; that is [a proposal](../planned-features/).

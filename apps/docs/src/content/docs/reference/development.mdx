Use Node.js 24.19.0 and npm 11.16.0, matching `.node-version` and the package metadata.

```sh
npm ci
npm run verify
npm run changeset:status
npm run pack:check
```

Verification runs formatting, lint, workspace typechecks, tests, and builds.
Tests use local fixtures and do not need production accounts. The public CLI
requires a patch Changeset for user-facing changes before 1.0.0. Publishing is
disabled until maintainers explicitly enable it.

## Full local workspace

From the repository root, run:

```sh
npm ci
npm run local
```

Open `http://127.0.0.1:3000` and choose **Create a local test account**. Use a test
email and a password of at least 12 characters. These are real Better Auth
accounts in an anonymous local Convex backend; no email is sent. GitHub, Convex
accounts, UploadThing credentials, and paid hosting are unnecessary for local
testing. The first run downloads the backend binary and needs internet access.

The app runs on port 3000, marketing on 4300, docs on 4301, and Convex on 3210
and 3211. Use the exact `127.0.0.1` origins. All services bind to loopback and
startup refuses occupied ports. Keep the terminal open; Ctrl-C stops the services
and preserves accounts, sessions, metadata, and bytes across restarts.

### Browser uploads

On Documents, choose **Upload document**. Drop one `.html` file or use the file
picker, edit the title, and choose **Save document**. You can also select a
`.planview` artifact bundle. Uploads share the hosted 8 MiB limit and account quota.
Use the CLI to upload a folder. Open a document title for its sandboxed preview;
its actions menu provides deletion. Background deletion removes stored bytes and
releases quota, and can wait until the next restart if the app is stopped.

### CLI and MCP

Startup builds the CLI. In another terminal, use a separate profile:

```sh
node apps/cli/dist/index.js --profile local-dev login --cloud-url http://127.0.0.1:3000
node apps/cli/dist/index.js --profile local-dev upload ./example.html
node apps/cli/dist/index.js --profile local-dev upload ./artifact-folder/
node apps/cli/dist/index.js --profile local-dev logout
```

Login opens a browser for local sign-in and **Authorize local CLI**. Configure
an OS browser opener such as `xdg-open` if your terminal cannot open one. Uploads
use the destination saved at login. Choose another profile name if `local-dev`
is already in use. The separate `publish` command still serves daemon snapshots
without an app account.

HTTP MCP clients connect to `http://127.0.0.1:3000/mcp` and complete OAuth using
the local account. Native clients registering an HTTP loopback callback must use
`application_type: "native"`, `token_endpoint_auth_method: "none"`, and PKCE S256.
Discovery is at `http://127.0.0.1:3000/.well-known/oauth-authorization-server`.
CLI upload credentials cannot be used as MCP access tokens.

### Data and development

The ignored `.planview-local/` directory contains the backend database, immutable
filesystem objects, generated development secrets, and isolated environment
configuration. Back it up while stopped to preserve the dataset. The runner does
not load or overwrite existing source `.env.local` files or select a cloud backend.
Do not start a separate `npx convex dev` in `apps/app` for this workflow.

App, site, and docs edits reload normally. Authored Convex sources are mirrored
into the isolated backend, including additions, renames, and deletions. Generated
API bindings sync back into `apps/app/convex/**/_generated/` so frontend types
follow backend changes. Review those binding changes alongside your code. Restart
after editing the runner itself.

### Reset explicitly

Log out the local CLI profile while the stack is running, then stop the runner:

```sh
node apps/cli/dist/index.js --profile local-dev logout
# Stop npm run local with Ctrl-C, then:
npm run local:reset -- --yes
npm run local
```

Reset refuses to run while the runner is active. It permanently deletes this
checkout's local accounts, sessions, document metadata and bytes, and generated
secrets. It preserves other CLI profiles, daemon snapshots, the shared Convex
binary cache, and hosted provider data. Old browser sessions become invalid.
These are development services for this computer; do not expose them publicly.

## Work on the docs

```sh
npm run dev --workspace @planview/docs
npm run typecheck --workspace @planview/docs
npm test --workspace @planview/docs
npm run build --workspace @planview/docs
npm start --workspace @planview/docs
```

Public URL configuration is read at build time. `PUBLIC_DOCS_URL` selects the
canonical docs origin and optional path prefix. `PUBLIC_APP_URL` and
`PUBLIC_SITE_URL` select workspace and marketing links. Copy `apps/docs/.env.example`
to `.env.local` when you need local overrides. Rebuild after changing a URL.
The production server reads `PORT` and exposes `/health`; it serves only built files.

## Work on the app with a hosted backend

Select a **development** Convex deployment you control and generate its bindings:

```sh
cd apps/app
npx convex deployment select <team>:<project>:dev/<name>
npx convex dev --once
```

Then return to the repository root:

```sh
npm run dev --workspace @planview/app
```

Use `apps/app/.env.example` and the app README for configuration. App and Convex
need compatible origins and matching server-side proof secrets. GitHub credentials
belong in the backend configuration; UploadThing credentials remain server-only.
Do not give them a `PUBLIC_` or `VITE_` prefix.

For a hosted MCP client, point it at your chosen app's `/mcp` route. The staging
endpoint is:

## Deployment boundaries

Marketing, docs, and app are separate services built from the repository lockfile.
A docs deployment needs public URL settings and a Node static server, not Convex
or UploadThing credentials. The cloud app needs a matching Convex deployment.

The merged quota implementation requires a coordinated upload maintenance window,
backend initialization, and compatible app release. Read `apps/app/README.md`
before deploying it beneath an older uploader. These development notes are not a
supported self-hosting installation recipe; that is [a proposal](../planned-features/).
